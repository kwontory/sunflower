# Sunflower

지금 있는 곳에서 해를 바라보려면 **어느 쪽으로 몇 도 돌아야 하는지** 알려주는 웹 애플리케이션.

- 운영 주소: https://sunflower-gamma-two.vercel.app
- 휴대폰에서 열면 방향 센서로 "오른쪽으로 32° 돌아보세요"처럼 안내하고,
  방향 센서가 없는 데스크톱에서는 "남쪽(170.9°)을 바라보세요"처럼 방위로 안내한다.

## 주요 기능

| 탭 | 내용 |
|---|---|
| 지금 | 기기 방향에 맞춰 도는 나침반 다이얼, 회전 안내 문장, 해의 방위각·고도, 데이터 상태와 출처 |
| 기록 | KST 날짜별 첫 번째 값, 서로 다른 두 날짜 비교, 기록 내보내기(JSON) |
| 상태 | 현재 데이터 상태, 조회·다음 갱신 시각, 마지막으로 받은 값, 기기(위치·방향) 상태, 요청 기록 |

- 화면 크기별 배치: 휴대폰 세로·가로, 태블릿 세로·가로, 데스크톱
- 오프라인: 한 번 연 뒤에는 네트워크가 없어도 앱이 열리고, 마지막으로 받은 값과 실패 안내를 보여준다.
  네트워크가 돌아오면 자동으로 다시 조회한다.
- 워드마크(`sunflower`)를 누르면 '지금' 화면으로 돌아간다.

## 동작 방식

1. 위치를 얻어 소수 둘째 자리(약 1.1km)로 반올림한다.
   다시 방문하면 마지막으로 받은 값의 반올림 좌표로 먼저 보여주고, 현재 위치는 동시에 확인한다 (D010).
2. [USNO celnav API](https://aa.usno.navy.mil/data/api)에서 현재 시각의 태양 방위각(`zn`)·고도(`hc`)를 받는다 (D003).
3. 응답을 검증한다. 형식이 틀리거나 값이 범위를 벗어나면 실패로 처리하고, 현재값처럼 보여주지 않는다.
   USNO는 해가 지평선보다 충분히 낮은 시간(심야)에는 응답에서 해 항목을 뺀다.
   다른 천체 항목은 정상인데 해 항목만 없으면 실패가 아니라 "해 없음"으로 처리한다 (D012).
4. 기기 방향 센서 값과 태양 방위각의 차이로 돌아야 할 방향과 각도를 계산한다.
   해의 고도가 0° 이하이거나 해 항목이 없으면 방향 안내 대신 달 그림과 "해가 지평선 아래" 안내를 보여준다.
   외부 요청이 실패한 동안에는 마지막으로 받은 값으로 방향을 안내하지 않는다.

### 데이터 상태 표시

화면에는 사용자 친화적인 말을 쓰고, 문서와 코드에는 설계 용어를 쓴다 (D007).

| 설계 용어 | 화면 표기 | 의미 |
|---|---|---|
| fresh | 실시간 · N분 전 | 검증을 통과한 새 값 (5분마다 갱신하므로 경과 시간을 항상 함께 표시) |
| cached | 최근 값 · N분 전 | 5분 안에 받은 값을 호출 없이 다시 사용 |
| stale | 오래된 값 · N분 전 | 조회 후 15분이 지난 값 |
| failed | 원인별 안내 ("응답이 늦어지고 있어요" 등) | 외부 요청 실패. 마지막으로 받은 값은 따로 표시하고 방향 안내에는 쓰지 않음 |
| sun-absent | 지평선 아래 · N분 전 확인 | USNO 정상 응답에 해 항목이 없음 (심야). 실패가 아니며 마지막으로 받은 값은 따로 표시 (D012) |
| 위치·방향 없음 | 방향 감지 안 됨 | 방향 센서가 없거나, 위치 권한이 없거나, 위치를 확인하지 못함 |

### 호출 정책 (D004, D005)

- 화면이 보일 때만 5분마다 자동 갱신한다. 새로고침은 60초 안에 다시 누르면 호출하지 않는다.
- 시간 초과·네트워크 오류·서버 오류·요청 과다(429)만 최대 2회 재시도한다.
  연속으로 실패하면 자동 갱신 간격을 5분 → 10분 → 20분 → 최대 30분으로 늘린다.

## 개인정보와 보안

- 정확한 GPS 좌표는 기기 안에서 바로 반올림하고, 반올림한 좌표만 USNO로 보낸다. 앱 운영자의 서버는 없다.
- 브라우저 저장소(localStorage)에는 마지막으로 받은 값과 KST 일별 기록만 저장한다 (반올림 좌표 포함).
- 외부 연결은 USNO 하나만 허용한다 (Content-Security-Policy). 서체는 앱에 포함해 외부 서체 서버를 부르지 않는다.
- 배포 응답에 보안 헤더를 붙인다 (`vercel.json`, D011): 다른 사이트의 iframe 삽입 금지, 파일 형식 추측 금지, referrer 미전송,
  위치·방향 센서는 이 사이트에서만 사용, 교차 출처 허용은 운영 주소로 제한.
- API 키·토큰 같은 비밀값이 없다. 저장소와 테스트에는 공개 장소(서울시청 등) 좌표만 쓴다.

## 실행 방법

Node.js 20 이상이 필요하다.

```bash
npm install
npm run dev        # 개발 서버 (http://localhost:5173)
npm test           # 테스트 (외부 API를 호출하지 않는다)
npm run typecheck  # 타입 검사
npm run build      # 배포용 빌드 (dist/)
```

위치와 방향 센서는 보안 연결(HTTPS 또는 localhost)에서만 동작한다.
휴대폰에서 방향 안내를 확인하려면 HTTPS 주소(배포 주소)로 접속해야 한다.

## 배포

Vercel에 정적 파일로 배포한다 (D008).

```bash
npx vercel deploy --yes          # 미리보기 (로그인 보호 주소)
npx vercel deploy --prod --yes   # 운영 (https://sunflower-gamma-two.vercel.app)
```

- 업로드 파일은 `.vercelignore` 허용 목록(`src`, `public`, `index.html`, `vercel.json`, 패키지·설정 파일)으로 제한한다.
- 운영 대표 주소는 공개이고, 미리보기·배포 고유 주소는 Vercel 로그인 보호가 걸려 있다.

## 기술 스택

- 화면: Vite + TypeScript (UI 프레임워크 없음), `render(state)` 함수로 그림 (D006)
- 테스트: Vitest (+ jsdom)
- 저장소: localStorage
- 오프라인: Service Worker (`public/sw.js`)
- 서체: IBM Plex Sans KR (본문), Sora (워드마크) — `@fontsource`로 앱에 포함 (D007)
- 배포: Vercel (D008), 보안 헤더는 `vercel.json` (D011)

```

  api/        USNO 요청(usno.ts), 응답 검증(validate.ts), 조회 결과 만들기(sun.ts)

  data/       재시도(retry.ts), 자동 갱신 간격(schedule.ts)
  storage/    마지막으로 받은 값·일별 기록(store.ts)
  sensors/    위치(location.ts), 기기 방향(heading.ts)
  app/        상태 관리와 흐름(controller.ts)
  ui/         화면(render.ts), 다이얼(dial.ts), 화면 문구(text.ts), 형식(format.ts)
  types.ts    모듈 간 공유 타입

public/       Service Worker, 파비콘
tests/        모듈별 테스트
docs/         기획·결정·진행 문서
```
